SOFTWARE ENGINEERING LAB INTERNAL II
POSSIBLE QUESTIONS, ANSWERS, STEP-BY-STEP PROCESSES AND COMMANDS
All 8 uploaded ZIP projects | Study guide based on SET-4 through SET-9 Word question papers
====================================================================================
SOURCE INSPECTION AND SCOPE
The Word papers repeatedly test: Docker Compose; Jenkins Scripted Pipeline; Maven build/test/WAR; Docker image build and push; GitHub webhooks and scheduled builds; Kubernetes/Minikube Deployment, NodePort, scaling, troubleshooting and rollback; AWS EC2/SSH/Security Groups; Nagios monitoring.
All eight ZIPs were inspected. They are Maven WAR web applications built mainly from JSP pages, web.xml and pom.xml. The project-specific WAR names and visible JSP pages are listed below.
Important archive findings: HMS and E-ticketing include Dockerfile + docker-compose.yml. ORS includes a Dockerfile only. BloodBank, Sport, Apartment, VehicleRental and Gym do not include Dockerfile/Compose. HMS and E-ticketing Compose files refer to ./db/init.sql, but that file is not present in the archive listing.
The archives do not show Java backend source or SQL schema/init files. Do not claim that database-backed authentication, booking, registration or persistence works just because MySQL starts. The Compose examples below are infrastructure practice templates; JDBC/database integration must be implemented separately.
JSP/WAR applications need a servlet container such as Tomcat. Nginx alone serves static content and does not execute JSP.
Use your own GitHub URL, Docker Hub username, Jenkins credential ID, EC2 IP and passwords. Never commit credentials. Commands are Bash/Linux/macOS unless stated.

PART 1 — COMMON EXAM QUESTIONS WITH ANSWERS
====================================================================================
Q1. What is Docker Compose?
Answer: A tool to define and run multiple containers from one YAML file. Use it for an app plus MySQL or Nagios. Start with docker compose up -d.

Q2. What is an image vs a container?
Answer: An image is a template; a container is a running or stopped instance created from that image.

Q3. Explain port mapping 8080:8080.
Answer: The left value is the host port; the right value is the container port. Browser access is http://localhost:8080.

Q4. What does depends_on do?
Answer: It controls service startup order, but basic depends_on does not guarantee database readiness. Use a healthcheck and service_healthy where supported.

Q5. Why use a named volume for MySQL?
Answer: It persists database files outside the container lifecycle. Removing/recreating a container will not automatically remove the named volume. Back up important data.

Q6. Stop Compose services without deleting them?
Answer: docker compose stop. It stops containers but preserves them.

Q7. Start the same stopped containers?
Answer: docker compose start.

Q8. Stop and remove containers and default network?
Answer: docker compose down. Add -v only if you intentionally want to delete named volumes and stored data.

Q9. Apply a changed Compose file?
Answer: docker compose up -d --build. Compose reconciles the services and recreates containers when needed.

Q10. Stop only one Compose service?
Answer: docker compose stop <service-key>. Use the service key from the YAML.

Q11. How do you inspect Compose?
Answer: docker compose config; docker compose ps; docker compose logs -f; docker compose logs -f <service>.

Q12. What is a Jenkins Scripted Pipeline?
Answer: A Groovy pipeline using node { } and stage('name') { } blocks to automate checkout, build, test, package, publish and notifications.

Q13. How do you skip Docker stages after Maven failure?
Answer: Allow sh 'mvn clean test package' to fail without swallowing the exception. Sequential stages after an uncaught failure are not executed. Do not catch and continue.

Q14. How should Docker Hub credentials be stored?
Answer: Store username and access token/password in Jenkins Credentials. Access by credential ID with withCredentials; never hard-code or echo secrets.

Q15. Why might a GitHub webhook fail?
Answer: Check Jenkins public reachability, webhook URL, push event, job GitHub hook trigger, repository/branch, firewall/proxy, webhook delivery response and Jenkins logs.

Q16. How do you schedule Jenkins at 6 PM daily?
Answer: Declarative: triggers { cron('0 18 * * *') }. In Scripted Pipeline, configure the job's Build periodically trigger or use properties([pipelineTriggers([cron('0 18 * * *')])]) where supported.

Q17. How do you email only on Jenkins failure?
Answer: Wrap stages in try/catch; in catch call emailext(to:..., subject:..., body:...) then rethrow the error. Configure SMTP and Email Extension Plugin first.

Q18. What is a Kubernetes Deployment?
Answer: A controller that maintains the requested number of Pods and supports rolling updates and rollback.

Q19. What is a NodePort Service?
Answer: A Service that exposes the application on a node port, normally 30000–32767, and forwards traffic to matching ready Pods.

Q20. Scale to four replicas and verify?
Answer: kubectl scale deployment/<name> --replicas=4; kubectl get deployment; kubectl get pods.

Q21. Why does Service ENDPOINTS show none?
Answer: Service selector may not match Pod labels, Pods may not be Ready, or resources may be in different namespaces. Compare kubectl get svc -o yaml and kubectl get pods --show-labels.

Q22. Troubleshoot Pending/CrashLoopBackOff Pods?
Answer: kubectl get pods -o wide; kubectl describe pod <pod>; kubectl logs <pod> --previous; kubectl get events --sort-by=.metadata.creationTimestamp. Check image, pull secret, resources, scheduling, config and app logs.

Q23. Rollback a Deployment?
Answer: kubectl rollout history deployment/<name>; kubectl rollout undo deployment/<name>; kubectl rollout status deployment/<name>.

Q24. Delete Deployment and Service?
Answer: kubectl delete deployment <name>; kubectl delete service <name>; verify with kubectl get deployments,svc,pods.

Q25. SSH to EC2 fails: what to check?
Answer: Instance state, public IP, correct username (Ubuntu commonly ubuntu), correct key, chmod 400 key.pem, TCP 22 inbound from your IP, public subnet route/Internet Gateway, NACL and OS firewall.

Q26. EC2 app works locally but not from browser?
Answer: Ensure app binds to 0.0.0.0, correct container port mapping, Security Group and OS firewall allow the host port, public IPv4 and route are correct.

Q27. How do you persist EC2 data?
Answer: Use EBS and configure attachment/mount/retention. For containers mount an EBS-backed directory or Docker volume. Configure DeleteOnTermination deliberately and back up.

Q28. Allow HTTP but restrict SSH?
Answer: Security Group inbound TCP 80 from intended users (0.0.0.0/0 only for public website; add IPv6 if needed); TCP 22 only from administrator public IP/CIDR.

Q29. What is Nagios?
Answer: A host/service monitoring system. It reports states such as OK, WARNING, CRITICAL and UNKNOWN; use its dashboard and logs to diagnose checks.

HMS — Hospital Management System
------------------------------------------------------------------------------------
Archive: HMS-main.zip
Maven output: target/hms.war
Visible JSP pages: index.jsp (hospital homepage), register.jsp (doctor appointment form)
Archive-specific note: Dockerfile and Compose exist; Compose references ./db/init.sql, which is absent from archive.

Q1. How do you build the project and generate its WAR?
Answer/process:
  unzip HMS-main.zip
  cd HMS-main
  mvn clean
  mvn test
  mvn package
  ls -lh target/hms.war
Expected: BUILD SUCCESS and target/hms.war exists. The POM uses WAR packaging; finalName determines the WAR filename.

Q2. How do you containerize and run the application using Tomcat?
Create Dockerfile in the project root:
  FROM tomcat:9.0
  COPY target/hms.war /usr/local/tomcat/webapps/ROOT.war
  CMD ["catalina.sh", "run"]
Commands:
  mvn clean package
  docker build -t <dockerhub-user>/hms:v1 .
  docker run -d --name hms-tomcat -p 8000:8080 <dockerhub-user>/hms:v1
  docker ps
  docker logs -f hms-tomcat
Browser: http://localhost:8000/

Q3. Write Docker Compose for the web application and MySQL.
Answer: create docker-compose.yml. This is a generic exam template; the supplied JSP project does not currently show JDBC integration.
  services:
    web:
      build: .
      container_name: hms-tomcat
      ports: ["8000:8080"]
      depends_on:
        db:
          condition: service_healthy
    db:
      image: mysql:8.0
      container_name: hms-db
      environment:
        MYSQL_DATABASE: appdb
        MYSQL_USER: appuser
        MYSQL_PASSWORD: change_me
        MYSQL_ROOT_PASSWORD: change_root_me
      ports: ["3307:3306"]
      volumes: ["app_db_data:/var/lib/mysql"]
      healthcheck:
        test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
        interval: 10s
        timeout: 5s
        retries: 10
  volumes:
    app_db_data:
Commands: docker compose config; docker compose up -d --build; docker compose ps; docker compose logs -f; docker compose stop; docker compose start; docker compose down.
Warning: docker compose down -v deletes named volumes and database data. To really use MySQL from JSP, add JDBC driver, connection code, schema and matching DB environment/config.

Q4. Create a Jenkins Scripted Pipeline to build/test/package and publish a Docker image.
Example Jenkinsfile (replace repository URL, branch, Docker Hub username and team email):
  node {
    def image = '<dockerhub-user>/hms:${BUILD_NUMBER}'
    try {
      stage('Checkout') {
        checkout([$class: 'GitSCM', branches: [[name: '*/main']],
          userRemoteConfigs: [[url: '<YOUR_GITHUB_REPOSITORY_URL>']]])
      }
      stage('Build and Test') {
        sh 'mvn clean test package'
        archiveArtifacts artifacts: 'target/*.war', fingerprint: true
      }
      stage('Docker Build') { sh "docker build -t ${image} ." }
      stage('Docker Push') {
        withCredentials([usernamePassword(credentialsId: 'dockerhub-creds',
          usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) {
          sh 'echo "$DOCKER_PASS" | docker login -u "$DOCKER_USER" --password-stdin'
          sh "docker push ${image}"
          sh 'docker logout'
        }
      }
    } catch (err) {
      emailext(to: '<team-email>', subject: "FAILED: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
        body: "Build failed. See ${env.BUILD_URL}console for details.")
      throw err
    }
  }
Jenkins setup: install Git, Pipeline and Email Extension plugins; configure JDK/Maven; add Docker Hub username/token as Jenkins credential ID dockerhub-creds; create Pipeline from SCM; set repo/branch; enable GitHub hook trigger; add webhook http(s)://<jenkins-host>/github-webhook/ for push events; run once and inspect Console Output.
Agent requirements: Maven, Docker CLI and Docker daemon access. Configure SMTP for emailext. Use your real default branch (main/master).

Q5. Deploy to Minikube, scale to four Pods and expose using NodePort.
Commands:
  minikube start
  minikube status
  kubectl create deployment hms --image=<dockerhub-user>/hms:v1
  kubectl scale deployment/hms --replicas=4
  kubectl expose deployment hms --type=NodePort --port=8080 --target-port=8080
  kubectl get nodes
  kubectl get deployments
  kubectl get pods -o wide
  kubectl get services
  minikube service hms --url
Open the returned URL. Ensure the image exists in Docker Hub (or load it into Minikube) and targetPort matches the app's actual listening port.
Troubleshooting: kubectl describe deployment hms; kubectl describe pod <pod>; kubectl logs <pod> --previous; kubectl get events --sort-by=.metadata.creationTimestamp; kubectl get svc hms -o yaml; kubectl get pods --show-labels.
Rollback: kubectl rollout history deployment/hms; kubectl rollout undo deployment/hms; kubectl rollout status deployment/hms.
Cleanup: kubectl delete service hms; kubectl delete deployment hms; minikube stop.

Q6. Deploy on AWS EC2 and make it accessible publicly.
Process: launch Ubuntu EC2 with key pair and public IPv4 in a public subnet; Security Group inbound TCP 22 from YOUR_IP/32 and TCP 8000 from the required client range; SSH; install Docker/Maven/Git; clone/copy project; mvn clean package; build and run container.
Commands:
  chmod 400 <key.pem>
  ssh -i <key.pem> ubuntu@<EC2_PUBLIC_IP>
  # after installing Docker and Maven, inside project directory:
  mvn clean package
  docker build -t hms:v1 .
  docker run -d --name hms-tomcat -p 8000:8080 hms:v1
  docker ps
  docker logs hms-tomcat
  curl -I http://localhost:8000/
Browser from your PC: http://<EC2_PUBLIC_IP>:8000/
Cleanup: docker stop hms-tomcat; docker rm hms-tomcat; terminate EC2 only when the lab is complete. Review EBS volumes/Elastic IPs separately.
If the question asks for static index.html with Nginx, use nginx:alpine and map 80:80. Nginx does not run JSP; use Tomcat for this WAR.

Q7. Monitor the application using Nagios.
Process: choose a Nagios Docker image; read that image's documentation for web port, default credentials and config paths; run it with a persistent config volume; attach Nagios and app containers to a shared Docker network; configure an HTTP service check against the app's container DNS name and internal port; reload Nagios; inspect Hosts/Services dashboard.
Troubleshoot CRITICAL: confirm app container is running; test app URL from inside monitoring network; check DNS/network attachment, service port/path, Nagios check plugin/command, config syntax and logs.
Example network commands: docker network create monitoring-net; docker network connect monitoring-net hms-tomcat; docker network connect monitoring-net <nagios-container>.
Nagios is not supplied in these archives; exact image and configuration are image-specific.

Q4. Create a Jenkins Scripted Pipeline to build/test/package and publish a Docker image.
Example Jenkinsfile (replace repository URL, branch, Docker Hub username and team email):
  node {
    def image = '<dockerhub-user>/gym:${BUILD_NUMBER}'
    try {
      stage('Checkout') {
        checkout([$class: 'GitSCM', branches: [[name: '*/main']],
          userRemoteConfigs: [[url: '<YOUR_GITHUB_REPOSITORY_URL>']]])
      }
      stage('Build and Test') {
        sh 'mvn clean test package'
        archiveArtifacts artifacts: 'target/*.war', fingerprint: true
      }
      stage('Docker Build') { sh "docker build -t ${image} ." }
      stage('Docker Push') {
        withCredentials([usernamePassword(credentialsId: 'dockerhub-creds',
          usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) {
          sh 'echo "$DOCKER_PASS" | docker login -u "$DOCKER_USER" --password-stdin'
          sh "docker push ${image}"
          sh 'docker logout'
        }
      }
    } catch (err) {
      emailext(to: '<team-email>', subject: "FAILED: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
        body: "Build failed. See ${env.BUILD_URL}console for details.")
      throw err
    }
  }

PART 3 — EXTRA SCENARIO QUESTIONS LIKELY FROM THE PAPERS
====================================================================================
Extra Q1. How do you map host port 9090 to Tomcat 8080?
Answer: docker run -d -p 9090:8080 <image>; Compose: ports: ['9090:8080']; browse http://localhost:9090/.

Extra Q2. How do you rebuild after changing JSP or WAR?
Answer: mvn clean package && docker build --no-cache -t <user>/<app>:v2 .; run a new container or update the Kubernetes image.

Extra Q3. How do you push an image manually?
Answer: docker login; docker tag <local-image> <user>/<repo>:tag; docker push <user>/<repo>:tag. Use an access token.

Extra Q4. What if the host port is already allocated?
Answer: Choose another host port such as 8090:8080; inspect docker ps and OS processes. The right-side container port must still match Tomcat.

Extra Q5. What if Docker build says target/*.war not found?
Answer: Run mvn clean package from the folder containing pom.xml; check target/<finalName>.war; run docker build from project root.

Extra Q6. What if Maven says no POM?
Answer: pwd; ls; cd into the extracted project root that contains pom.xml; rerun Maven.

Extra Q7. What if a Kubernetes image pull fails?
Answer: kubectl describe pod <pod>; inspect ErrImagePull/ImagePullBackOff; verify image/tag, registry visibility, credentials and imagePullSecrets.

Extra Q8. How do you inspect a crashing Pod's previous logs?
Answer: kubectl logs <pod> --previous; kubectl describe pod <pod>; kubectl get events --sort-by=.metadata.creationTimestamp.

Extra Q9. What is port-forward vs NodePort?
Answer: port-forward is a temporary local debug tunnel; NodePort exposes a Service through a node port.

Extra Q10. How do you configure rolling update and rollback?
Answer: kubectl set image deployment/<name> <container>=<image>:v2; kubectl rollout status deployment/<name>; kubectl rollout undo deployment/<name>.

Extra Q11. How do you find why Jenkins failed?
Answer: Open the build in Jenkins, inspect Pipeline/Stage View, click the failed stage, read Console Output and stack trace; verify agent tools and credentials.

Extra Q12. How do you verify GitHub webhook delivery?
Answer: GitHub repository Settings > Webhooks > select webhook > Recent Deliveries; inspect HTTP response and redeliver after fixing.

Extra Q13. How do you create a static Nginx website on EC2?
Answer: Create index.html; docker run -d --name static-site -p 80:80 -v "$PWD":/usr/share/nginx/html:ro nginx:alpine; allow TCP 80; browse http://<public-ip>.

Extra Q14. How do you inspect EC2 public IP with AWS CLI?
Answer: aws ec2 describe-instances --instance-ids <id> --query 'Reservations[].Instances[].[State.Name,PublicIpAddress]' --output table (requires AWS CLI credentials/permissions).

Extra Q15. Stop vs terminate EC2?
Answer: Stop powers off an EBS-backed instance while retaining it and its EBS volumes; terminate deletes the instance and may delete volumes according to DeleteOnTermination.

Extra Q16. What does EBS provide?
Answer: Persistent block storage for EC2. Attach/mount carefully and use snapshots/backups.

Extra Q17. How to send both success and failure emails?
Answer: Use try/catch/finally or post-build result handling; send success email only when currentBuild.currentResult == 'SUCCESS', and failure email otherwise. SMTP and Email Extension Plugin must be configured.

Extra Q18. What should you do if a Service has no endpoints?
Answer: Compare selector labels to Pod labels; verify Pods are Ready and in same namespace; kubectl get endpoints <service>; kubectl get pods --show-labels; kubectl describe service <service>.

Extra Q19. How do you remove Compose containers but preserve DB data?
Answer: docker compose down (do not add -v). Named volumes remain.

Extra Q20. How do you remove Compose containers and DB data?
Answer: docker compose down -v. This is destructive; only do it when data can be discarded.

- Give the command, explain its purpose, then give a verification command.

- EC2 public IP is not enough: verify route, Security Group, OS firewall, bind address and Docker port mapping.
