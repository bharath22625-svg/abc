DEVOPS LAB EXTERNAL – COMMANDS AND PROCEDURES QUICK REFERENCE

Use this as a reading/revision sheet. Replace placeholders such as
USERNAME, REPO_URL, YOUR_PUBLIC_IP and EMAIL with your own values.
Commands may differ slightly depending on Windows/Linux, installed
versions, college lab setup and configured credentials.

  --------------------------------------
  1. GIT – LOCAL AND REMOTE REPOSITORY
  --------------------------------------

A. Create a multi-folder project

mkdir StudentManagement cd StudentManagement mkdir src docs echo Student
Management Project > README.md echo public class Student {} > src.java

For Windows PowerShell, the above echo commands work. On Linux/macOS,
use: mkdir -p src docs echo “Student Management Project” > README.md

B. Initialize and save changes

git init git status git add . git status git commit -m “Initial commit”
git log git log –oneline

Meaning: - git init: initializes a local repository. - git status:
displays changed, staged and untracked files. - git add .: stages
changes. - git commit -m “message”: saves staged changes in local
history. - git log: displays commit history.

C. Connect to a private GitHub repository

1.  Create an EMPTY private repository on GitHub. Do not initialize it
    with README if you already have a local project with commits.
2.  Connect and push:

git branch -M main git remote add origin
https://github.com/USERNAME/REPOSITORY.git git remote -v git push -u
origin main

For later uploads: git add . git commit -m “Updated project” git push

D. Clone an existing repository

git clone https://github.com/USERNAME/REPOSITORY.git cd REPOSITORY

E. Get updates from the remote repository

git fetch origin git pull origin main

-   fetch downloads remote updates but does not merge them into the
    current branch.
-   pull fetches and integrates remote changes into the current branch.

F. Branching and merging

git branch git branch feature git checkout feature # Or create and
switch in one command: git checkout -b feature

git add . git commit -m “Added feature” git checkout main git merge
feature git branch -d feature

Newer alternative to checkout: git switch main git switch -c feature

G. Compare and temporarily store changes

git diff git diff –staged git stash git stash list git stash pop

H. Undoing changes

git revert COMMIT_ID # Creates a new commit that reverses the selected
commit.

git reset –soft HEAD~1 # Moves HEAD back one commit but keeps changes
staged.

git reset –mixed HEAD~1 # Moves HEAD back one commit and leaves changes
unstaged (default reset mode).

Avoid git reset –hard unless you intentionally want to discard changes.

I. Remove tracked files

git rm filename git add . git commit -m “Removed file”

J. Private repository collaboration

1.  Repository owner creates a private GitHub repository.
2.  Owner opens Settings > Collaborators (or repository access) and
    invites teammates.
3.  Teammates accept the invitation.
4.  Each teammate clones the repository.
5.  Each teammate creates a separate branch, edits files, commits and
    pushes.
6.  Teammates create Pull Requests.
7.  Owner reviews and merges the Pull Requests.
8.  Everyone runs git pull to receive merged changes.

K. Merge conflict resolution

A conflict can occur when two people modify overlapping lines.

git pull origin main

If Git reports a conflict: 1. Open the conflicted file. 2. Find conflict
markers: <<<<<<< HEAD ======= >>>>>>> branch-name 3. Edit the file and
keep the correct combined content. 4. Remove all conflict markers. 5.
Save the file.

git status git add . git commit -m “Resolved merge conflict” git push

L. Patch commands

Create a patch containing unstaged changes: git diff > changes.patch

Apply a patch: git apply changes.patch

Create a patch from the latest commit: git format-patch -1 HEAD

Apply a commit patch: git am 0001-*.patch

Useful additional Git commands: git remote -v git remote add origin
REPO_URL git remote remove origin git show COMMIT_ID git tag git tag
v1.0 git push origin v1.0

  2. MAVEN – JAVA BUILD AND DEPENDENCY MANAGEMENT
  -------------------------------------------------

A. Check Maven and Java

java -version javac -version mvn -version

B. Generate a basic Maven Java project

mvn archetype:generate -DgroupId=com.student
-DartifactId=StudentManagement
-DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false

cd StudentManagement

C. Standard Maven structure

StudentManagement/ pom.xml src/ main/ java/ test/ java/ target/

-   pom.xml: project configuration, dependencies and plugins.
-   src/main/java: application source code.
-   src/test/java: test source code.
-   target: generated build output.

D. Common Maven commands

mvn validate mvn compile mvn test mvn package mvn verify mvn install mvn
deploy mvn clean mvn clean install mvn dependency:tree

Meaning: - validate: checks project structure and required
information. - compile: compiles main source code. - test: runs tests. -
package: creates JAR/WAR according to packaging configuration. - verify:
runs checks after packaging. - install: installs the artifact in the
local Maven repository. - deploy: publishes the artifact to a configured
remote repository. - clean: removes the target directory. -
dependency:tree: displays dependency hierarchy.

E. pom.xml example

4.0.0 com.student StudentManagement 1.0-SNAPSHOT jar

    <dependencies>
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.13.2</version>
            <scope>test</scope>
        </dependency>
    </dependencies>

F. Add a dependency

Place a dependency inside the section of pom.xml. Example MySQL
connector:

com.mysql mysql-connector-j 8.4.0

G. JAR versus WAR

-   JAR: Java Archive, commonly used for Java libraries and standalone
    applications.
-   WAR: Web Application Archive, used for Java web applications
    deployed to a servlet containers such as Tomcat.
-   Set jar or war in pom.xml.

H. Dependency conflicts

mvn dependency:tree

Resolve by explicitly selecting a compatible version in
dependencyManagement or dependencies, or excluding an unwanted
transitive dependency.

  3. DOCKER CLI – IMAGES AND CONTAINERS
  ---------------------------------------

A. Check Docker

docker –version docker info

B. Download and inspect an image

docker pull nginx docker images

C. Create and run a container

docker run -d -p 8080:80 –name myserver nginx

Open http://localhost:8080 in a browser.

-   -d: detached/background mode.
-   -p 8080:80: host port 8080 maps to container port 80.
-   –name: assigns a container name.
-   nginx: image name.

D. Container commands

docker ps docker ps -a docker stop myserver docker start myserver docker
restart myserver docker logs myserver docker inspect myserver docker
stats docker top myserver docker exec -it myserver bash docker rm
myserver

If bash is unavailable in an image, try: docker exec -it myserver sh

E. Image commands

docker images docker pull nginx docker rmi nginx

A container using an image may need to be removed before the image can
be deleted.

F. Network commands

docker network ls docker network create mynetwork docker run -d –name
web –network mynetwork nginx docker network inspect mynetwork docker
network rm mynetwork

G. Volume commands

docker volume ls docker volume create myvolume docker run -d –name
data-container -v myvolume:/data nginx docker volume inspect myvolume
docker volume rm myvolume

A volume stores data outside the container’s writable layer so it can
persist after the container is removed.

  -----------------------------------------------
  4. DOCKERFILE – BUILD, PUSH AND PULL AN IMAGE
  -----------------------------------------------

A. Create a project folder

mkdir MyWebApp cd MyWebApp

Create index.html:

My Docker App
Hello from Docker!
B. Create a file named exactly Dockerfile (no extension)

FROM nginx:latest COPY index.html /usr/share/nginx/html/ EXPOSE 80

Common Dockerfile instructions: - FROM: base image. - WORKDIR: sets
working directory. - COPY: copies files from build context into image. -
RUN: executes commands while building the image. - EXPOSE: documents the
container port; it does not publish the port. - CMD: default
command/arguments when container starts. - ENTRYPOINT: main executable
for the container.

C. Build and run

docker build -t mywebapp . docker images docker run -d -p 8080:80 –name
webcontainer mywebapp

Open http://localhost:8080.

D. Push image to Docker Hub

1.  Create/sign in to an account at https://hub.docker.com/
2.  Login:

docker login

3.  Tag the image:

docker tag mywebapp YOUR_USERNAME/mywebapp:v1

4.  Push:

docker push YOUR_USERNAME/mywebapp:v1

E. Pull on another computer

docker pull YOUR_USERNAME/mywebapp:v1 docker run -d -p 8080:80
YOUR_USERNAME/mywebapp:v1

  5. DOCKER COMPOSE – MULTI-CONTAINER APPLICATION
  -------------------------------------------------

A. Create a folder and a file named compose.yaml

Example:

services: web: image: nginx ports: - “8080:80”

database: image: mysql:8 environment: MYSQL_ROOT_PASSWORD:
change_this_password volumes: - mysql_data:/var/lib/mysql

volumes: mysql_data:

For a real database, use a strong password and preferably a secrets
mechanism rather than storing a real password directly in a file.

B. Compose commands

docker compose up docker compose up -d docker compose ps docker compose
logs docker compose logs web docker compose stop docker compose start
docker compose restart docker compose build docker compose pull docker
compose down

-   up: creates and starts services.
-   up -d: starts in background.
-   ps: displays services/containers.
-   logs: displays service logs.
-   down: stops and removes project containers and network.
-   named volumes are normally retained by down; use docker compose down
    -v to remove declared volumes too. Be careful: this deletes stored
    data.

Compose creates a default network. Services can normally reach each
other using their service names, for example the database hostname
“database”.

  6. JENKINS – MANUAL FREESTYLE JOB WITH MAVEN
  ----------------------------------------------

A. Requirements - Jenkins running. - Java/JDK configured. - Maven
configured in Jenkins (Manage Jenkins > Tools). - Git plugin
installed. - Maven Integration plugin if using “Invoke top-level Maven
targets”.

B. Create a Freestyle job

1.  Open Jenkins, commonly http://localhost:8080.
2.  Select New Item.
3.  Enter a job name.
4.  Select Freestyle project and click OK.
5.  Under Source Code Management, select Git.
6.  Enter GitHub repository URL.
7.  Add credentials if the repository is private.
8.  Specify branch, for example */main.
9.  Under Build Steps, choose Invoke top-level Maven targets.
10. Enter goals: clean install
11. Save.
12. Click Build Now.
13. Open the build number and Console Output.

If the Maven integration build step is unavailable, configure a shell or
Windows batch step with the Maven command, and ensure Maven is installed
and available to Jenkins.

C. Build status - SUCCESS: completed successfully. - FAILURE: build
failed. - UNSTABLE: build completed but one or more checks/tests
reported problems. - ABORTED: build was stopped.

  -----------------------------------------------------------
  7. JENKINS – DECLARATIVE AND SCRIPTED PIPELINES, TRIGGERS
  -----------------------------------------------------------

A. Declarative Jenkinsfile

Save a file named Jenkinsfile in the root of the Git repository:

pipeline { agent any

    stages {
        stage('Build') {
            steps {
                echo 'Building project'
                sh 'mvn clean compile'
            }
        }

        stage('Test') {
            steps {
                echo 'Running tests'
                sh 'mvn test'
            }
        }

        stage('Package') {
            steps {
                echo 'Packaging project'
                sh 'mvn package'
            }
        }
    }

}

For a Windows Jenkins agent, replace sh with bat: bat ‘mvn clean
compile’

B. Scripted Pipeline example

node { stage(‘Build’) { echo ‘Building project’ sh ‘mvn clean compile’ }

    stage('Test') {
        echo 'Running tests'
        sh 'mvn test'
    }

    stage('Package') {
        echo 'Packaging project'
        sh 'mvn package'
    }

}

C. Declarative versus Scripted - Declarative: uses pipeline {}, agent,
stages {} and a structured syntax. - Scripted: uses node {} and Groovy
scripting; more flexible. - Both can automate build, test and deployment
stages.

D. Build triggers

1.  Build periodically: runs according to a schedule.
2.  Poll SCM: Jenkins periodically checks source control for changes.
3.  GitHub webhook: GitHub notifies Jenkins when an event such as a push
    occurs.
4.  Build after another project: starts after another job completes.

Example Jenkins cron schedule: H/5 * * * *

This schedules a run approximately every five minutes. Jenkins uses a
hash-based distribution for H.

E. GitHub webhook setup

1.  Ensure Jenkins is reachable from GitHub through a public URL or
    suitable tunnel. A Jenkins URL that only works as localhost is not
    reachable by GitHub.
2.  In GitHub repository, open Settings > Webhooks > Add webhook.
3.  Payload URL: https://YOUR_PUBLIC_JENKINS_URL/github-webhook/
4.  Content type: application/json
5.  Select Just the push event.
6.  Add/save webhook.
7.  In Jenkins job configuration > Build Triggers, enable: GitHub hook
    trigger for GITScm polling
8.  Save and test by pushing a commit to GitHub.
9.  Check Jenkins build history and Console Output.

F. Screenshots useful for a lab record - Jenkins dashboard. - Freestyle
job configuration. - Git repository URL/branch configuration. - Maven
build goals. - Jenkinsfile/pipeline configuration. - Pipeline stage
view. - Console Output with successful build. - GitHub webhook
configuration and delivery status. - Email notification, if configured.

  ----------------------------------
  8. JENKINS – EMAIL NOTIFICATIONS
  ----------------------------------

A. Install and configure 1. Manage Jenkins > Plugins. 2. Install Email
Extension Plugin. 3. Manage Jenkins > System. 4. Configure Extended
E-mail Notification with SMTP server, port, authentication, sender and
security settings. 5. Use an app password or appropriate SMTP credential
where required; do not put account passwords directly into a
Jenkinsfile.

B. Example post block for a Declarative Pipeline

post { success { emailext( subject: ‘Build Successful’, body: ‘Project
build was successful.’, to: ‘YOUR_EMAIL@example.com’ ) }

    failure {
        emailext(
            subject: 'Build Failed',
            body: 'Project build failed.',
            to: 'YOUR_EMAIL@example.com'
        )
    }

}

Email delivery requires a working SMTP configuration and the Email
Extension plugin.

  9. MINIKUBE AND KUBERNETES
  ----------------------------

A. Important terms - Cluster: group of machines managed by Kubernetes. -
Node: machine in the cluster. - Pod: smallest deployable Kubernetes
unit. - Deployment: manages replicated pods and updates. - Service:
provides network access to pods. - Scaling: changing the number of
replicas.

B. Minikube commands

minikube start minikube status minikube dashboard minikube stop minikube
delete

C. kubectl commands

kubectl get nodes kubectl get pods kubectl get pods -A kubectl get
deployments kubectl get services kubectl describe pod POD_NAME kubectl
logs POD_NAME kubectl delete pod POD_NAME

D. Deploy Nginx

minikube start kubectl create deployment nginx –image=nginx kubectl get
deployments kubectl get pods kubectl expose deployment nginx
–type=NodePort –port=80 kubectl get services minikube service nginx

The last command opens/accesses the service using Minikube’s service
URL.

E. Scale deployment

kubectl scale deployment nginx –replicas=3 kubectl get pods kubectl
scale deployment nginx –replicas=1

F. YAML deployment example

Save as nginx.yaml:

apiVersion: apps/v1 kind: Deployment metadata: name: nginx spec:
replicas: 3 selector: matchLabels: app: nginx template: metadata:
labels: app: nginx spec: containers: - name: nginx image: nginx ports: -
containerPort: 80

Apply and inspect:

kubectl apply -f nginx.yaml kubectl get deployments kubectl get pods
kubectl describe deployment nginx

Delete:

kubectl delete -f nginx.yaml

  10. NAGIOS AND NGINX MONITORING
  ---------------------------------

A. Nagios Nagios is an infrastructure monitoring tool used to monitor
hosts, services and applications and generate alerts.

Nagios states: - OK: service is healthy. - WARNING: a threshold or
warning condition is reached. - CRITICAL: serious problem. - UNKNOWN:
status cannot be determined.

Important terms: - Host: machine being monitored. - Service: component
being monitored. - Plugin: program/script that performs a monitoring
check. - Notification: alert sent to an administrator.

B. Run a Nagios Docker image (example image)

docker pull jasonrivers/nagios:latest docker run –name nagios -d -p
8080:80 jasonrivers/nagios:latest docker ps docker logs nagios

Open: http://localhost:8080

Login details and setup can vary by image/version. Refer to the image’s
documentation for its configured credentials. Port 8080 must be free.

C. Install and manage Nginx on Ubuntu

sudo apt update sudo apt install nginx sudo systemctl start nginx sudo
systemctl status nginx sudo systemctl enable nginx sudo systemctl stop
nginx sudo systemctl restart nginx

Open http://localhost or the server’s IP address if network/firewall
rules permit.

Nagios can monitor whether a host responds and whether the Nginx HTTP
service is available. Actual monitoring checks require appropriate
Nagios plugins/configuration.

  11. AWS FREE TIER / AWS ACCOUNT AND EC2 BASICS
  ------------------------------------------------

A. Account creation procedure

1.  Visit https://aws.amazon.com/
2.  Choose Create an AWS Account.
3.  Enter email address and account name.
4.  Verify email.
5.  Set account root password.
6.  Provide requested contact and payment verification details.
7.  Complete identity/payment verification as requested by AWS.
8.  Select a support plan.
9.  Sign in to AWS Management Console.
10. Enable MFA for the root user and do not use root for routine work.
11. Create an IAM administrative user/role for daily administration
    where appropriate.

Important: AWS account creation may require a valid payment method and
verification. Free Tier eligibility, credits, quotas and pricing change
over time. Check the current AWS Free Tier page and pricing before
launching resources. Some resources can incur charges even when
experimenting.

B. Important AWS services

-   EC2: virtual servers in the cloud.
-   S3: object storage.
-   IAM: users, roles and permissions.
-   VPC: isolated virtual network.
-   RDS: managed relational database.
-   CloudWatch: metrics, logs and alarms.
-   Lambda: serverless code execution.

C. Basic EC2 launch procedure

1.  Open AWS Console > EC2.
2.  Select Launch instance.
3.  Enter instance name.
4.  Choose an eligible Amazon Machine Image (AMI), such as Ubuntu.
5.  Select an instance type after checking current free-tier/credit
    eligibility.
6.  Create or select a key pair and download the private key safely.
7.  Configure network/security group.
8.  Allow SSH (port 22) only from your own IP where possible.
9.  Allow HTTP (port 80) if hosting a public website.
10. Launch instance.
11. Wait until instance checks pass.
12. Copy its public IPv4 address.

Common ports: - 22: SSH. - 80: HTTP. - 443: HTTPS.

D. Connect to Ubuntu EC2 from a terminal

On a machine with SSH:

ssh -i “KEY_FILE.pem” ubuntu@YOUR_PUBLIC_IP

On Windows, use PowerShell/OpenSSH or an available SSH client. Protect
the .pem key; never share it or upload it to GitHub.

E. Stop or terminate resources

In EC2 console, select the instance and choose Stop or Terminate as
required. Stopping and terminating have different effects. Storage, IP
addresses and other attached resources may still incur charges. Delete
unused resources and review billing.

  12. UBUNTU VIRTUAL MACHINE AND PUBLIC WEB APP DEPLOYMENT
  ----------------------------------------------------------

A. Create a VM (example using VirtualBox)

1.  Install Oracle VirtualBox.
2.  Download an Ubuntu Desktop or Server ISO from the official Ubuntu
    website.
3.  Open VirtualBox > New.
4.  Enter VM name and select Linux/Ubuntu.
5.  Allocate memory and CPU according to your computer’s available
    resources.
6.  Create a virtual hard disk.
7.  Attach the Ubuntu ISO to the virtual optical drive.
8.  Start the VM and follow the Ubuntu installer.
9.  Create a username and password.
10. Restart and remove/eject the ISO when installation completes.

B. Update Ubuntu

sudo apt update sudo apt upgrade -y

C. Install Nginx

sudo apt install nginx -y sudo systemctl status nginx

Find the VM’s IP address:

ip addr

D. Create a sample web page

sudo nano /var/www/html/index.html

Enter:

My Web App
Hello from Ubuntu VM!
Save in nano: - Ctrl+O, Enter to save. - Ctrl+X to exit.

Restart Nginx:

sudo systemctl restart nginx

E. Test locally

Open in the VM: http://localhost

From another computer on the same network, try: http://VM_IP_ADDRESS

F. Make the web app publicly accessible

For a cloud VM such as EC2: 1. Assign/use a public IP address. 2. Allow
inbound HTTP port 80 in the cloud security group. 3. Ensure the Ubuntu
firewall allows HTTP if UFW is enabled:

sudo ufw allow ‘Nginx HTTP’ sudo ufw status

4.  Open: http://YOUR_PUBLIC_IP

For a VirtualBox VM: - NAT networking does not automatically make a VM
publicly accessible. - For host access, configure port forwarding (host
port such as 8080 to guest port 80). - Bridged networking may make the
VM accessible on the local network. - Public internet access requires
router/firewall/network configuration and a public reachable address. Do
not expose SSH or other services without proper security.

G. Useful Ubuntu commands

pwd ls cd DIRECTORY mkdir DIRECTORY touch filename nano filename ip addr
sudo apt update sudo apt install PACKAGE sudo systemctl start nginx sudo
systemctl status nginx sudo systemctl restart nginx sudo systemctl
enable nginx sudo ufw status

  ----------------------------------
  14. LAST-MINUTE VIVA DEFINITIONS
  ----------------------------------

Git: Distributed version control system. GitHub: Online platform for
hosting Git repositories and collaboration. Repository: Storage location
for project files and history. Commit: Saved snapshot of staged changes.
Branch: Separate line of development. Merge conflict: Occurs when Git
cannot automatically combine changes. Maven: Java build automation and
dependency management tool. POM: Project Object Model; Maven’s project
configuration. Dependency: External library required by a project.
Plugin: Tool that performs a build task. JAR: Java Archive. WAR: Web
Application Archive. Docker: Platform for building and running
containers. Image: Template used to create containers. Container:
Isolated running instance of an image. Dockerfile: Instructions used to
build a Docker image. Docker Compose: Tool for managing multi-container
applications. Jenkins: Automation server for CI/CD. Pipeline: Automated
sequence of build/test/deploy stages. Webhook: HTTP event notification
sent to another system. Kubernetes: Container orchestration platform.
Minikube: Tool for running a local Kubernetes cluster. Pod: Smallest
deployable Kubernetes unit. Deployment: Kubernetes resource that manages
pods. Nagios: Infrastructure monitoring tool. Nginx: Web server and
reverse proxy. AWS EC2: Cloud virtual server service. S3: AWS object
storage service. IAM: AWS identity and access management service.
Ubuntu: Linux operating system distribution. SSH: Secure Shell, used for
secure remote terminal access.
